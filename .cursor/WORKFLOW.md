# AI自动化开发工作流

## 完整流程

```
┌─────────────────────────────────────────────────────────────┐
│ 1. AI每日扫描                                                │
│    - GitHub Action定时触发                                   │
│    - Agent分析代码                                           │
│    - 自动创建Issues [标签: ai-proposed]                      │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 2. 👤 人工Review（唯一主动介入点）                           │
│    - 浏览新创建的Issues                                      │
│    - 评估优先级和可行性                                      │
│    - 评论 /approve 批准开发                                  │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 3. AI自动开发                                                │
│    - /approve触发Agent启动                                   │
│    - Agent ID记录在Issue中                                   │
│    - 自动创建分支、编码、测试                                │
│    - 自动创建Draft PR                                        │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 4. 👤 人工Code Review（被动响应）                            │
│    - 收到PR通知                                              │
│    - Review代码变更                                          │
│    - 如需修改：在PR评论具体要求                              │
│    - Agent自动响应评论继续修改（同一Agent，保持上下文）      │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│ 5. 👤 最终Merge（被动响应）                                  │
│    - 确认PR符合预期                                          │
│    - Merge to main                                           │
│    - Agent自动关闭                                           │
└─────────────────────────────────────────────────────────────┘
```

## 人工介入原则

### ✅ 人应该做的
1. **需求决策**：决定做什么（批准Issue）
2. **质量把关**：Review代码质量
3. **最终确认**：Merge决策

### ❌ 人不应该做的
1. ~~手动创建分支~~
2. ~~编写代码~~
3. ~~运行测试~~
4. ~~创建PR~~
5. ~~更新文档~~

## 特殊场景

### 场景1：人工创建Issue
人手动创建Issue → 评论`/approve` → 进入自动开发流程
**✅ 完全支持**

### 场景2：现有Issue要AI处理
给旧Issue添加`/approve`评论 → Agent开发
**✅ 完全支持**

### 场景3：紧急修复
1. 手动创建Issue描述问题
2. 立即评论`/approve`
3. Agent快速开发修复
**✅ 完全支持**

### 场景4：PR需要修改
在PR评论具体要求 → Agent自动响应（需实现follow-up）
**⚠️ 需要实现PR评论触发**
