# AI需求扫描Agent指令

## 目标
自动扫描代码库，发现潜在的改进点，并创建Issue供人工审批。

## 扫描范围

### 1. 代码中的TODO/FIXME
扫描所有源代码文件，提取待办事项：
```bash
grep -rn "TODO\|FIXME" --include="*.js" --include="*.ts" --include="*.py" .
```

### 2. 测试覆盖率缺失
- 找出没有测试的重要函数
- 建议补充测试用例

### 3. 代码质量问题
- 重复代码（可重构）
- 过长函数（可拆分）
- 复杂度过高的函数

### 4. 依赖更新
- 检查`package.json`/`requirements.txt`中的过期依赖
- 安全漏洞扫描

## Issue创建规则

每个发现的需求创建一个Issue，格式如下：

**标题**：`[AI提议] {需求简述}`

**标签**：
- `ai-proposed` （必须）
- `enhancement` 或 `bug` 或 `refactor`
- 风险等级：`low-risk` / `medium-risk` / `high-risk`

**内容模板**：
```markdown
## 📋 需求来源
- [ ] 代码TODO
- [ ] 测试覆盖率
- [ ] 代码质量
- [ ] 依赖更新
- [ ] 其他

## 📝 描述
{详细描述问题和建议的改进}

## 🎯 预期收益
{这个改进会带来什么好处}

## ⚠️ 风险评估
- 风险等级：低/中/高
- 影响范围：{哪些模块会受影响}
- 测试难度：简单/中等/复杂

## 💻 相关代码
{文件路径和行号}

## 🔧 建议实现方案
{如果有明确的实现思路，在这里描述}

## ⏱️ 工作量估算
- 开发：{小时数}
- 测试：{小时数}

---
**此Issue由AI自动生成，等待人工审批**
```

## 执行流程

1. 扫描各个来源
2. 对每个发现，评估是否值得成为Issue
3. 创建Issue（使用gh CLI或GitHub API）
4. 汇总报告：本次创建了多少个Issue
5. 等待人工审批

## 重要规则

- **不要重复创建**：检查是否已存在类似Issue
- **优先级排序**：按重要性和紧急性排序
- **可行性过滤**：明显不可行的需求不创建
- **信息完整**：确保每个Issue有足够信息供人工决策
